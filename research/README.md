# Research

Analysis, design directions and working notes that are not descriptions of
the current implementation. The [architecture](../architecture/README.md)
pages say what the code does; these pages say what is missing, why it
matters, and how to approach it.

- [Production readiness](production-readiness/index.md): every gap between
  v1 and a deployment a team can trust, one brief per area, with current
  state, failure scenarios, requirements, design direction and work breakdown.

Briefs are dated by their git history. A brief that describes a gap that has
since closed should be deleted, and the architecture page updated, rather
than kept as a record.
